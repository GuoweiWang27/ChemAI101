# CHEMAI101 旗舰反应课堂体验二期设计

**日期：** 2026-08-27
**状态：** 已定稿，按已确认的五旗舰方案进入实施
**目标用户：** 教师为主（约 70%），招生官与项目评审为辅（约 30%）

## 1. 背景与目标

一期已经建立 40 个教材反应的动画资料库、统一播放控制和自动审计门禁，但多数反应仍停留在“几个原子移动”的示意层。二期不平均美化全部 40 个反应，而是把五个具有代表性的反应做成可用于课堂讲解、又能体现项目深度的旗舰案例：

1. 钠与水（`na-h2o`）
2. 硫在氧气中燃烧（`s-o2`）
3. 氨与氯化氢（`nh3-hcl-smoke`）
4. 乙烯与溴（`c2h4-br2`）
5. 氧化钙与水（`cao-water-exothermic`）

核心成果不是更复杂的装饰动画，而是一套将宏观实验现象、微观粒子变化、配平方程式和课堂提问同步起来的讲解体验。

## 2. 产品原则

- **先教学，后展示。** 每个动效都要帮助教师解释现象、条件或机理，不能只追求视觉冲击。
- **宏观与微观同步。** 学生看到实验现象时，应能同时理解粒子、键或离子的变化。
- **可暂停、可追问。** 教师可以在关键节点暂停，不需要进入单独的测验系统。
- **化学事实与演示抽象分开。** 视觉简化必须显式标注；不能把示意图伪装成真实比例、真实速率或真实实验录像。
- **事实型项目叙事。** 面向招生官的说明只呈现真实完成的功能、审计指标和迭代过程，不虚构教师背书、用户数量或效果数据。
- **兼容一期。** 新的旗舰数据和渲染能力不能破坏现有 40 个反应、首页计数器或旧版动画。

## 3. 范围与非目标

### 3.1 本期范围

- 五个旗舰反应升级为 L2/L3 课堂体验。
- 每个旗舰反应包含宏观轨、微观轨、方程式轨和教师提示轨。
- 桌面端提供宏观/微观并排模式；移动端提供同步标签切换。
- 支持关键教学节点、教师提问卡、局部重播和同步播放。
- 增加独立的“项目如何做成”说明入口，展示设计目标、技术架构、审计方法和真实状态。
- 扩展自动审计，覆盖旗舰反应的阶段、原子守恒、映射、事件和教学节点。

### 3.2 非目标

- 不把全部 40 个反应都升级为 L3。
- 不建设账号、班级、作业、评分、学习记录或教师后台。
- 不引入 CMS、三维引擎或需要长期维护的新型运行时。
- 不制作或伪装真实实验视频。
- 不在没有返回教师审核清单的情况下标记“教师已审核”“课堂已验证”。
- 不更改一期计数器的统计口径和持久化机制。

## 4. 核心课堂体验

### 4.1 进入方式

反应库中的旗舰卡片显示“课堂旗舰”标识。进入详情后默认打开“课堂演示”模式：

- 左侧或上方：宏观实验现象。
- 右侧或下方：微观粒子/键变化。
- 底部：方程式、阶段进度、播放控制。
- 教师提示默认收起，点击后显示当前节点的提问和讲解建议。

普通反应继续使用一期详情页，不强行套用旗舰布局。

### 4.2 桌面端与移动端

桌面端（宽度不小于 1024px）默认宏观与微观并排，两个轨道共享时间轴。教师可以单独放大一个轨道，但不会改变另一轨的播放位置。

移动端默认一次显示一个轨道，通过“现象 / 微观”标签切换。切换时保持当前阶段和时间点，避免教师反复寻找位置。方程式和播放控制固定在可见区域内，不遮挡主要动画。

### 4.3 时间轴与教学节点

每个反应包含 4–6 个化学阶段。时间轴上用小标记显示教学节点：

- 到达节点时仅做轻量提示，不强制打断连续播放。
- 教师可开启“节点自动暂停”；开启后动画在节点暂停并显示问题。
- 每个问题提供“展开提示”，但不做答题判分和数据存储。
- 支持只重播当前阶段，方便课堂重复观察。

### 4.4 同步高亮

当阶段涉及特定原子、离子或化学键时：

- 微观轨高亮对应对象。
- 方程式轨同步高亮对应化学式、系数或生成物。
- 宏观轨只突出可观察现象，不用粒子颜色暗示真实实验颜色。

## 5. 场景数据架构

在兼容现有 scene v1/v2 的前提下，为旗舰反应增加 scene v3。旧数据继续由原渲染器处理；只有声明 v3 的反应进入旗舰播放器。

```ts
interface FlagshipReactionSceneV3 {
  version: 3
  reactionId: string
  durationMs: number
  stages: FlagshipStage[]
  macroTrack: MacroEvent[]
  microTrack: MicroEvent[]
  equationTrack: EquationCue[]
  teachingMoments: TeachingMoment[]
  cameraShots?: CameraShot[]
  evidence: EvidenceRecord[]
  review: {
    chemistryStatus: 'pending' | 'passed' | 'blocked'
    teacherStatus: 'pending' | 'reviewed'
  }
}
```

### 5.1 数据职责

- `stages`：定义反应的化学叙事顺序和可重播区间。
- `macroTrack`：描述火焰、烟、褪色、放热、形态变化等可观察现象。
- `microTrack`：描述粒子接近、键断裂/形成、离子组合、电子变化等微观事件。
- `equationTrack`：将动画事件映射到反应物、生成物、条件和系数。
- `teachingMoments`：定义暂停点、课堂问题、提示和预期观察。
- `cameraShots`：只控制构图、缩放和关注区域，不承载化学事实。
- `evidence`：记录教材、权威资料或项目内部审核依据；不直接显示成教师背书。
- `review`：将化学审核和教师审核分开，任何 UI 文案必须尊重这两个状态。

### 5.2 组件拆分

- `FlagshipReactionPlayer`：协调时间轴、播放状态和轨道同步。
- `MacroPhenomenonStage`：渲染宏观实验现象。
- `MicroMechanismStage`：沿用并扩展现有粒子、离子和键事件渲染器。
- `EquationCueBar`：显示方程式和同步高亮。
- `TeachingMomentCard`：显示问题、提示和预期观察。
- `ReactionStageTimeline`：显示阶段、节点和局部重播入口。
- `ProjectStoryPage`：展示项目动机、架构、审计和真实进展。

播放器只读取场景数据，不在组件中硬编码某个具体反应的化学结论。

## 6. 五个旗舰反应脚本

### 6.1 钠与水：L3 基准案例

**宏观现象：** 钠浮在水面、熔成小球、快速游动、逐渐消失，并可能出现燃烧现象。所有表现均标为教材化演示，不模拟真实危险实验。

**微观阶段：**

1. 钠原子与水分子初始分布。
2. 界面接触与电子转移提示。
3. 钠离子和氢氧根形成。
4. 氢原子重组形成氢气分子并逸出。
5. 放热与宏观运动/燃烧现象建立对应。

**课堂问题示例：** “为什么钠会浮在水面？”“气泡来自哪个反应物？”“方程式系数为什么是 2:2:2:1？”

### 6.2 硫在氧气中燃烧

**宏观现象：** 固体硫受热熔化、点燃后发出蓝色火焰，生成气体。颜色表达必须与教材描述一致，并避免把示意火焰当作光谱测量。

**微观阶段：**

1. 硫和氧气处于反应前状态。
2. 加热提供反应条件。
3. 氧分子键变化与硫氧键形成。
4. 二氧化硫分子生成并扩散。

**课堂问题示例：** “加热是反应物还是反应条件？”“生成物为什么写作 SO₂？”“蓝色火焰属于宏观证据还是微观解释？”

### 6.3 氨与氯化氢

**宏观现象：** 两种气体扩散后出现白烟，白烟区域随扩散相遇位置形成。动画不把烟雾位置当作定量扩散实验结论。

**微观阶段：**

1. 氨分子和氯化氢分子从两侧分布。
2. 两种分子扩散并接近。
3. 质子转移与铵离子、氯离子形成。
4. 氯化铵微粒聚集，对应宏观白烟。

**课堂问题示例：** “白烟是气体还是固体小颗粒？”“为什么两种无色气体会产生可见现象？”“微观图中电荷如何守恒？”

### 6.4 乙烯与溴

**宏观现象：** 溴的颜色逐渐褪去。若使用溴水或其他体系，场景标题、条件和证据必须一致，不混用实验条件。

**微观阶段：**

1. 乙烯双键和溴分子清晰展示。
2. 反应物接近，双键反应区域被高亮。
3. 双键中的一条键发生变化，溴溴键断裂。
4. 两个碳溴键形成，生成加成产物。
5. 宏观颜色减少与溴分子消耗同步。

**课堂问题示例：** “褪色能说明什么？”“乙烯分子中哪一部分发生变化？”“加成反应前后原子数是否改变？”

### 6.5 氧化钙与水

**宏观现象：** 固体与水接触后放热、体系温度上升并形成较疏松的氢氧化钙。蒸汽或白雾只能在证据支持的条件下表现。

**微观阶段：**

1. 氧化钙晶格与水分子分开显示。
2. 水分子靠近固体表面。
3. 离子环境变化并形成氢氧化物结构示意。
4. 能量释放通过独立热量提示表达。
5. 生成物结构与宏观形态变化建立对应。

**课堂问题示例：** “温度升高说明能量如何变化？”“水是反应物还是只起溶剂作用？”“为什么产物的俗名是熟石灰？”

## 7. 项目说明入口

新增独立项目说明页或等价抽屉入口，面向教师和招生官回答四个问题：

1. **为什么做：** 教材现象、方程式和微观机理经常被分开呈现。
2. **怎么做：** 以数据驱动的双轨时间轴同步宏观现象、微观事件和方程式。
3. **如何保证可信：** 使用原子守恒、事件映射、证据记录、移动端 QA 和人工审核清单。
4. **现在做到哪里：** 明确显示反应总数、旗舰案例数、自动审计结果和教师审核真实状态。

页面可以展示代码架构和迭代前后对比，但不得写入无法证明的使用量、课堂成效、教师评价或招生结果。首页计数器如果展示累计使用数据，继续使用现有真实数据源和降级策略。

## 8. 化学审核与教师审核

### 8.1 化学审核门禁

每个旗舰反应上线前必须：

- 方程式与反应条件经过资料核对。
- 原子守恒和电荷守恒（适用时）通过自动审计。
- 微观事件与方程式对象有完整映射。
- 宏观现象、颜色和状态描述存在证据记录。
- 动画中必要的教学简化有可见说明。

### 8.2 教师审核状态

教师审核是独立于化学审核的外部流程。当前已有审核清单，但没有完成返回记录，因此默认状态为 `pending`。在真实教师完成审核前：

- 产品可以标记“待教师复核”或不显示该状态。
- 不能标记“教师认证”“课堂验证通过”。
- 项目说明页可如实写“已建立教师审核清单，正在等待实际课堂反馈”。

## 9. 失败与降级行为

- v3 数据缺字段或审计不通过时，该反应不进入旗舰播放器，回退到一期动画并记录诊断信息。
- 宏观轨资源加载失败时，微观轨、方程式和教学节点仍可使用；界面显示简短的资源失败提示。
- `prefers-reduced-motion` 开启时，减少相机移动、粒子漂移和强闪烁，保留阶段切换与教学信息。
- 小屏幕或低性能设备优先保证文字、方程式和控制可用，再降低粒子数量、模糊和光效。
- 项目说明页的数据读取失败时，不显示旧缓存数字冒充最新状态；使用“暂不可用”文案。

## 10. 测试与验收

### 10.1 数据与自动审计

- 五个旗舰反应均使用有效 scene v3 数据。
- 每个反应至少 4 个化学阶段、3 个教学节点。
- 四个由 L1 升级的旗舰反应通过完整的方程式、原子映射和事件审计；`na-h2o` 保持并扩展现有 L3 门禁。
- 所有旗舰反应的宏观、微观和方程式轨在阶段边界保持同步。
- 教师审核状态默认保持 `pending`，除非仓库中存在可追溯的已返回审核记录。
- 40 个反应仍可打开；非旗舰反应无运行时回归。

### 10.2 交互与可访问性

- 播放、暂停、重播当前阶段、跳转节点和宏微观切换均可键盘操作。
- 教学问题在动画暂停时可读，不依赖颜色传达答案。
- 减少动态模式下无强闪烁和大幅相机运动。
- 方程式、按钮和提示在 200% 文本缩放下不发生关键遮挡。

### 10.3 浏览器 QA

至少覆盖：

- 1280×720：常见课堂投屏笔记本。
- 1440×900：桌面完整双轨体验。
- 390×844：移动端标签切换与控制区。

检查首屏、五个旗舰反应、普通反应回退、项目说明页、首页计数器、反应库数量以及资源加载失败状态。

### 10.4 上线门禁

只有在以下条件全部满足后才能部署生产：

- 类型检查、测试、构建和旗舰审计全部通过。
- 本地三种视口 QA 通过。
- 主任务完成独立代码审计，无阻断级问题。
- 提交仅包含本期相关改动，推送成功。
- Cloudflare 部署成功，生产资源对应目标提交。
- 生产环境重复执行关键页面、五个旗舰、计数器和移动端验证。

## 11. 实施拆分

实施计划应按以下依赖顺序拆解，具体文件与测试命令由代码勘察后确定：

1. scene v3 类型、校验器和测试。
2. 双轨播放器、时间轴和教学节点通用组件。
3. 五个旗舰反应数据与专用宏观效果。
4. 旗舰详情布局及桌面/移动响应式体验。
5. 项目说明入口与真实状态数据。
6. 审计脚本、回归测试、构建和本地浏览器 QA。
7. 主任务审计、修复、提交、推送、Cloudflare 部署和生产验证。

## 12. 完成定义

二期完成意味着：教师可以用五个反应完成“观察现象—解释微观变化—对应方程式—提出课堂问题”的连续讲解；招生官可以从项目说明中看见明确的问题意识、技术设计、化学审核和诚实的迭代边界；同时一期的 40 个反应、首页数据和现有部署稳定性不受破坏。
